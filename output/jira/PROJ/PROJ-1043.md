# [PROJ-1043] Patch fflate 0.8.2 → 0.8.3 in routescout-v2

**URL:** https://teqplaybv.atlassian.net/browse/PROJ-1043

## Description

1 open Dependabot alert on routescout-v2 came back from triage as needing a fix rather than a dismissal. Installed versions are what package-lock.json resolves today; where that could not be read the version is marked unknown rather than guessed.
Dependencies to patch
fflate: 0.8.2 → 0.8.3 (moderate, alert #56). Pulled in by mapbox-gl → fflate; react-map-gl → mapbox-gl → fflate.
Root dependencies
The project's own dependencies that bring the vulnerable versions in. Bumping one of these may close several alerts at once; where it cannot, the transitive version has to be pinned instead.
mapbox-gl brings in fflate 0.8.2
react-map-gl brings in fflate 0.8.2
What triage found
#56 fflate unzipSync can enter an infinite loop when parsing malformed ZIP64 archives — fflate 0.8.2 is in the production tree via mapbox-gl 3.5.1, a runtime dependency. node_modules is not installed, so I could not grep mapbox-gl for unzipSync and cannot establish whether the vulnerable ZIP64 path is reachable. Failing closed. Recommended: Bump fflate to 0.8.3. Non-breaking: 0.8.3 satisfies mapbox-gl's ^0.8.1 range, so this is a lockfile-only change (npm update fflate) with no manifest or API impact. 
https://github.com/teqplay/routescout-v2/security/dependabot/56
Definition of done
fflate is on 0.8.3 or laterThe build and the test suite pass on the bumped versionsEvery alert listed above is closed on GitHub
