# [PTO-391] As a PTO user I want to also use the non-real-time data (like satellite + dynamic) to increase quality of detections

**URL:** https://teqplaybv.atlassian.net/browse/PTO-391  
**Type:** Story | **Status:** Done | **Priority:** Medium  
**Reporter:** Richard van Klaveren | **Assignee:** Unassigned  
**Created:** 2023-12-13 | **Updated:** 2024-03-04  
**Board:** PTO board  

## Description

For port of Salalah, coverage is not so great and seems only real-time messages are taken into account for stop detection, sometimes leading to strange situations with the timeline where things are pretty clear visible but timestamps detected are way less accurate.... since quite some timestamps get detected at the same time (coverage), there are quite some 0 durations (e.g. arrival at berth is first real-time location in port, so pilot_on_board = mooring_time = berth start (edited) 


Agreed that it is worth to dive into the option of classifying ports as low coverage: those ports need to also take the non-real data into account. Doing that now would potentially open a box of pandora, so for this cycle let's report to APMT that accuracy of the data is low, leading to less trustable numbers. 

We should check what are the side-effects of using for both (r)events and vesselvoyage recalculation, and what are the benefits if we enable this for the ports with low coverage.
