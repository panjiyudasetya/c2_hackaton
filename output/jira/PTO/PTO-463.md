### Wouter Naloop — 2024-02-09

# There is a bug in the code where we use 2 reference points to search for the eos 

For the inbound timeframe:
Left bound: Start of the previous voyage
Right bound: first vesselvoyage stop of the Visit

For the outbound timeframe:
Left bound: last vesselvoyage stop of the Visit
Right bound: next voyage end time

This goes wrong when there is a first or last vesselvoyage stop that is not inside of the eos area

# Another case where we don’t detect the eos area entry/exit is when it did not happen from the previous voyage until it entered the new port. This is the case when 2 ports are close to eachother and the eos area contains both ports. 
This is most obvious for 2 visits after eachother to the same port so USNYC - Voyage - USNYC
Where the first visit most likely will have the eos entry and no eos exit. And the second visit likely has no eos entry but will have the eos exit
