# [PTO-139] PTO frontend: use scenario search endpoint during report generation, to either select a scenario to reuse or run from scratch

**Parent:** [PTO-134] As a PTO user I want to select a scenario to be reused manually, or run it from scratch  

## Description

The PTO frontend is going to use a search/query endpoint to look for scenarios that have run already, so the user can select to reuse a specific scenario explicitly.There will be a new endpoint in the PTO backend to request that:
{{POST /<prefix>/revents/scenario/query}}
(I don't know the {{prefix}} part, but it's the same as with {{POST /<prefix>/start}} that is used to start a run.)That endpoint takes the exact same input as {{/start}}, and it queries scenarios with full and partial overlap.

The {{matching}} part is a list of scenarios that have an "exact" match, so the start and end data are exactly contained within that scenario. They may have more ports or a larger time window though.
The {{overlapping}} part has scenarios with partial overlap between the requested start and end.

{noformat}{
  "matches": [],
  "overlaps": [
    {
      "id": "22c3528e-ef34-45b6-80ec-3988cf19d960",
      "phase": "FINISHED",
      "queued": "2023-08-15T08:46:41.780Z",
      "window": {
        "from": "2023-03-01T00:00:00Z",
        "to": "2023-03-07T00:00:00Z"
      },
      "windowMarginInDays": 0,
      "events": [
        "DIFF",
        "ANCHOR",
        "AREA",
        "ENCOUNTER"
      ],
      "interests": [
        {
          "type": "AREA",
          "area": {
            "type": "PORT",
            "id": "E57297BAEF6EE30BCDE04E8DFAED7E389A8AF210"
          }
        }
      ]
    }
  ]
}
{noformat}

The frontend would only need to display these fields as a minimum:

* {{window.from}} & {{window.to}} - compared to the provided {{startDate}} and {{endDate}}, there is full overlap if the scenario is in the {{matches}} list, there is partial overlap in the {{overlaps}} list so then the frontend should also display how much this time window is off (for example the user wanting a report starting from 2023-05-01, but a scenario was only run starting from 2023-06-01)
* {{queued}} - when the scenario was queued to be run, was it run last week/month/etc.

Optionally it could also display:

* {{phase}} - whether the scenario is {{FINISHED}}, {{PROGRESSING}}, {{QUEUED}} etc., could be useful to let the user know if the underlying data is immediately available ({{FINISHED}}) or it will take some time still ({{PROGRESSING}} or {{QUEUED}})



When the user selects a specific scenario to be reused, then the {{reventsScenario}} should be set to the clicked scenario {{id}}.
