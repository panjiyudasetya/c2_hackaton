## Description

h2. Description

Found during the frontend dependency triage. RoutesEntryPoint stores the pre-login path and search params in session storage and replays it into a {{navigate()}} call and a {{<Link to>}} after login, no validation on either. A {{//}}- or {{/\}}-prefixed deep link is same-origin per the browser but resolves as a protocol-relative off-origin redirect once replayed through the Link.

Bumping react-router-dom to 7.18.0 does not fix this on its own, checked the actual installed package: {{<Link to="//example.com/x">}} still resolves to a real cross-origin href. Fix is {{isSafeRedirectPath()}} in {{src/utils/redirect.ts}}, applied at the point RoutesEntryPoint captures the path, so nothing unsafe ever gets stored.
