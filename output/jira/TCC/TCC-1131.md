## Description

h2. Description

Dependabot flags a high severity in {{auth0-js}} (CVE-2026-42280 / GHSA-8qjv-jj2q-x832, improper permission checking) for everything {{>= 8.11.0, <= 9.32.0}}. First fixed version is {{10.0.0}}. This one actually ships in the browser bundle in the login path, unlike most of the dependabot alerts on these repos which are build/test tooling that never reaches the browser, so it is worth doing.

Affected:

* csi on {{auth0-js@9.29.1}} (alert #58 / #11)

Both use it the same minimal way ({{WebAuth}}, {{authorize()}}, {{parseHash()}}, {{logout()}}) and then POST the {{accessToken}} / {{idToken}} to the backend on {{/auth/login/auth0}}.

h2. How to fix

Frontend only, no backend change needed. Bump {{auth0-js}} to {{^10}} (latest is {{10.2.0}}) in poma and csi and reinstall. The only breaking change in v10 is that HS256 apps now get an {{invalid_token}} back from {{parseHash()}} instead of it silently passing. RS256 apps are not affected, and since both apps use an API {{audience}} with access tokens they are already on RS256, so the flow, {{responseType}} ({{id_token token}}), {{responseMode}} and the tokens we send to the backend all stay the same.

One thing to check in the Auth0 dashboard (not code, not backend): Application > Advanced Settings > OAuth > JsonWebToken Signature Algorithm is RS256 for both apps. Should already be the case.

Release notes: https://github.com/auth0/auth0.js/releases/tag/v10.0.0

h2. Definition of Done

* -{{auth0-js}} upgraded to v10 in csi-
* -Auth0 signature algorithm confirmed RS256 for both apps-
* -Login redirect + token handoff tested on dev-
* -Changes released on dev and prod-
* Dependabot alerts closed (poma #75, csi #58)
