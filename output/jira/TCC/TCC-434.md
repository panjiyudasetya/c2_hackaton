## Description

h2. Description

Richard shared already some in the VesselVoyage channel, but what basically happens is that VesselVoyage traces tend to get broken all of a sudden. Most likely this has to do with Voyages being resumed when passing through a port, but that is mainly a gut feeling based when looking at the bahaviour.

Richard his message:

{quote}Traces of this vessel are really bad in recent voyages... in timeline I do see events on places where there is no trace, feels like something real bad is happening here? [https://vesselvoyage.teqplay.nl/#/ships/9401984|https://vesselvoyage.teqplay.nl/#/ships/9401984|smart-link]  --> timeline issue was my issue, selected [+backend.teqplay.nl+|http://backend.teqplay.nl/] for a source..... so result, traces are only really bad in{quote}

*Open standing issue right now:*

Post-processing slow
 a. With locking improved, check if it does something?
 b. Check where there is a strain (ShipHistory?)

Given that the lock improvement will make more calls to ShipHistory, and that ShipHistory seems to be having issues with performance, improve said performance so the backlog of post-processing wont take 2+ months to finish.

Lets start with spending around 2 days to see what is going on and what is happening. Once we have a feeling what is going wrong and where the pain points are, lets improve and make a plan of attack.

h2. Dependencies

Direct impact on PortReporter where this trace is shown for all vessels. However, this has been in there for months already (so whenever we decided to move away from VesselVoyage V1 in PortReporter). This does mean that it still should have some importance to get this fixed.
