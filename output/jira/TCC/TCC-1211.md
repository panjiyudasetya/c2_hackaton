# [TCC-1211] Alongside dimensions swapped in encounter monitor

**URL:** https://teqplaybv.atlassian.net/browse/TCC-1211

**Reporter:** Michel Wilson | **Assignee:** Michel Wilson

## Description

In 
DetectionService.areBothAlongside
 (around line 613), code passes the wrong vessel's dimensions into isAlongside.
Current code:
val vessel1Alongside =
    isAlongside(
        service = vessel1,
        seaVessel = vessel2,
        seaVesselDimensions = shipInfoDatasource.getTransponderPosition(vessel1.ship.mmsi),
        maxDistance = maxDistance,
    )
val vessel2Alongside =
    isAlongside(
        service = vessel2,
        seaVessel = vessel1,
        seaVesselDimensions = shipInfoDatasource.getTransponderPosition(vessel2.ship.mmsi),
        maxDistance = maxDistance,
    )
isAlongside
 uses 
seaVesselDimensions
 to compute the bow/stern positions of the vessel passed as 
seaVessel
. So the first call should pass the dimensions of 
vessel2
, and the second the dimensions of 
vessel1
. Both calls are mirrored the wrong way round, meaning the alongside rectangle is always built from the other ship's hull.
Confirm the bug by reading isAlongside and both call sites.
Fix the argument pairing.
Run the tests and see if they still pass. If test expectations do shift, summarise exactly which STS scenarios changed and how, so a reviewer can sanity-check the detection is now better and not merely different.
