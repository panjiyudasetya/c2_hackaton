# [TCC-205] Fix an issue where CSI client still uses buildUri

**URL:** https://teqplaybv.atlassian.net/browse/TCC-205  
**Type:** Bug | **Status:** Done | **Priority:** Medium  
**Reporter:** Darius Wattimena | **Assignee:** Darius Wattimena  
**Created:** 2025-06-06 | **Updated:** 2025-06-12  
**Board:** TCC board  
**Parent:** [TCC-152] Production Issues  

## Description

Calls like {{search}} still use the old spring boot 2 way of uris. This doesn’t work anymore with newer version of Spring Boot 3.4

Because of this client calls that are wrong will return:
{{java.lang.IllegalArgumentException: Not enough variable values available to expand 'name'}}

Example code that now goes wrong:

{noformat}    fun search(
        shipFilter: ShipFilter,
        limit: Int? = null,
        onlySeaVessels: Boolean? = null
    ): List<ShipRegisterInfo> = restTemplate.getForObject<Array<ShipRegisterInfo>>(
        url = buildUri(
            "$PREFIX/search/query",
            mapOf(
                "name" to shipFilter.name,
                "mmsi" to shipFilter.mmsi,
                "imo" to shipFilter.imo,
                "eni" to shipFilter.eni,
                "shipType" to shipFilter.shipType,
                "limit" to limit,
                "onlySeaVessels" to onlySeaVessels
            )
        )
    ).toList(){noformat}

Call should be replaced with {{getForObjectWithParams}} or equivalents.
