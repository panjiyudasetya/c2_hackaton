## Description

h2. Description

Implement the speed handling logic such as currently done in the platform for the eta predictor: 

* cache the last 30 minutes of speed data for every ship
* update this history based on ais-diff messages
** currently, the {{LocationRequestUpdater}} service subscribes to NATS
** this should be moved outside of this service to a dedicated NATS service bean thingy
** in this bean, the update should be distributed to the {{LocationRequestUpdater}} and the new speed service, both need to process the update messages
* if history is not present when needed: pull 30 minutes of data from ship history (service for this already exists)
* two options for prediction speed:
** ship is accelerating: use average of last 1/3 of data
** otherwise: use average of 30 minutes of data
