# [TCC-1217] Prevent stale/missing portATD causing incorrect “In Port” status

**URL:** https://teqplaybv.atlassian.net/browse/TCC-1217  
**Type:** Bug | **Status:** To Do | **Priority:** Medium  
**Reporter:** Joost Dambrink | **Assignee:** Unassigned  
**Created:** 2026-09-10 | **Updated:** 2026-09-14  
**Labels:** NeedsRefinement  

## Description

Problem
Some vessels have a 
portATA
 but no 
portATD
 in VesselVoyage even though AIS shows they have clearly left the port.
SmartFleet uses this state for the 
In Port
 filter, causing stale visits to incorrectly appear as still in port.
Cases
HAI GONG YOU 606 — IMO 9301873:
 Rotterdam arrival 
portATD
 missing; vessel departed long ago.
Dorys — IMO 9331244:
 Singapore departure 
portATD
 missing; vessel is already around Hormuz.
V GAS OHIO — IMO 9640645:
 Singapore 
portATD
 missing; vessel is already in the western Pacific.
To do
Investigate the cases, identify why the ATDs are missing, and implement a systemic fix/prevention mechanism.
Do not fix these vessels individually.
 The goal is to prevent these cases from happening or remaining stale so customers don't see incorrect 
In Port
 data.
Original report
In PortReporter, we have an option for the SmartFleet dashboard to filter voyages that are "In Port".
This filter checks either the departure or the arrival visit's 
portATA
 is set and 
portATD
 isn't (that we obtain from VesselVoyage).
However, when applying the filter, sometimes we get some vessels that are obviously not in a port (in the middle of a journey according to the AIS location), but their departure or arrival times state that they are still in Port.
HAI GONG YOU 606 — IMO 9301873

Arrival 
portATD
 is missing, but it obviously departed a long time ago. As a result, it gets classified in SmartFleet as a voyage from Antwerp to Rotterdam incorrectly (still in Rotterdam).
Dorys — IMO 9331244

According to its location, it's in Hormuz, but the departure port (SGSIN) misses 
portATD
. As a result, it gets classified in SmartFleet as a voyage from SGSIN still in the port.
V GAS OHIO — IMO 9640645

Singapore ATD is not set, but it's already in the western Pacific. As a result, it gets classified in SmartFleet as a voyage from SGSIN still in the port.
The cases are not a lot, but enough to display wrong data to customers.
The solution is not to recalculate or fix individually each ship's dataset, but to identify each case's cause and set measures so they don't happen.
We shouldn't rely on spotting these cases ourselves and requesting individual data fixes, but prevent them from happening as much as we can. Otherwise, we run the risk that customers see these issues before we do.
Please analyse the cases and let us know if you have any doubt.
More examples can be found in PortReporter's 
Tankers from Singapore
 fleet (prod), under the 
In Port
 tab.
