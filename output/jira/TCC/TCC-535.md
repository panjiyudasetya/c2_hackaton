# [TCC-535] Investigate time-series data storage for Vesselvoyage completeness + ETA predictor

**URL:** https://teqplaybv.atlassian.net/browse/TCC-535  
**Type:** Task | **Status:** To Do | **Priority:** Medium  
**Reporter:** Michel Wilson | **Assignee:** Unassigned

**Board:** TCC board  

## Description

It turns out that Prometheus creates a time series for every value combination assigned to the labels for a metric. Since we want to record unlocode + vessel type, the number of time series gets unreasonably big. Therefore, we should investigate which alternatives there are, that are suitable for storing time series data _and_ storing high cardinality data, i.e., data with many different label values. Note that for the ETA predictor, we are going to have a similar problem when storing metrics per port, as we want to store performance data for every port with different labels (travel time, vessel type, …?).

Options to explore:

* reduce cardinality somehow?
* mysql/postgres, but what is the impact when querying large time ranges?
* alternative time series databases (influx, …?)
