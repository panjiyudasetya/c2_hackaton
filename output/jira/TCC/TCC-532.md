## Description

h2. Description

When CSI Internal DATA does a call to ship history to get all ships it currently results in a timeout.

CSI calls the {{/v0/ship}} endpoint which goes to ShipHistory (Which would be this endpoint GET [https://internalapi.teqplay.dev/v0/ship|https://internalapi.teqplay.dev/v0/ship] using platform {{username-password-auth}}). While this call works fine locally in something like Insomnia, it does not when done from CSI itself.

You can trigger the cron that is failing by hand using the following endpoint: POST [https://csibackenddata-internal.teqplay.nl/v1/externalTicketCreation/ais|https://csibackenddata-internal.teqplay.nl/v1/externalTicketCreation/ais]
