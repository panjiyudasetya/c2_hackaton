## Description

h2. Description

Right now when doing any kind of recalculation we have to also recalculate the main port.

Otherwise you would get the following crash result:

{noformat}SCENARIO_INTERESTS_RESOLVE_AREA_REQUIRES_ONLY_MAIN_PORTS{noformat}

This isn’t really nice, given that you might only want to recalculate a small part and not the full port. Most likely you want to have the following:

# Load in AIS for only the sub port EOSP area
# Load in the main port for area events

This most likely still have some caveats? What happens with existing data in VesselVoyage? How can this be recalculated without breaking existing visits?

h2. Scope

* What is part of this change?
* What is not part of this change?

h2. Dependencies

Context mapping team currently is effected by this, given that they sometimes want to recalculate only a sub port.
