# [TCC-643] Adjust API endpoint option to be able to only request barge SOFs

**URL:** https://teqplaybv.atlassian.net/browse/TCC-643  
**Type:** Sub-task | **Status:** Done | **Priority:** Medium  
**Reporter:** Darius Wattimena | **Assignee:** Darius Wattimena  
**Created:** 2026-01-12 | **Updated:** 2026-01-20  
**Board:** TCC board  
**Parent:** [TCC-546] Add support for non-sea vessels to be processed in VesselVoyage  

## Description

After a discussion with the PTO team we came to the conclusion that having the ability to request SOFs by port needs an option to only get back barges.

With the current solution of {{includeNonSeaVessels}} this would not work given it would return both sea-vessels and barges in the response when this is set to {{true}}.

----

The new solution will be as followed:

{{includeNonSeaVessels}} will be removed in favour of a new {{vesselType}} param where you can provide {{SEA_VESSEL}} and {{BARGE}} as value.

So this will become:

# Only sea vessels is {{sof/byPort?vesselType=SEA_VESSEL}}
# Only barges is {{sof/byPort?vesselType=BARGE}}
# Both sea vessel and barges is {{sof/byPort?vesselType=SEA_VESSEL,BARGE}}

{panel:bgColor=#eae6ff}
Do note that {{vesselType=SEA_VESSEL}} will be the default value when nothing is provided to ensure nothing will break for the existing consumers.
{panel}
