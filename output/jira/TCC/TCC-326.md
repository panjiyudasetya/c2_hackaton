## Description

h2. Description

Case where it is going wrong:[https://vesselvoyagedev.teqplay.nl/#/ships/9341328/story/3674893f-6151-45fc-ab11-aaa7aed12ead.VISIT|https://vesselvoyagedev.teqplay.nl/#/ships/9341328/story/3674893f-6151-45fc-ab11-aaa7aed12ead.VISIT|smart-link] 

Somehow it is possible that the fallback end is before the start, this shouldn’t be possible. Might be related to the old multi-threading issue that we had. Regardless fallbacks shouldn’t be set into the negative.

h2. Scope

Set up a fix and depending on how severe the issue also go back into existing data and fix the end times where possible.

h2. Dependencies

Both PTO and Projects team are effect by this, given that the issue might have popped up for any Visit. However, impact might be low given that we did fix a lot of issue on PROD, so the data should be much better compared to DEV.
