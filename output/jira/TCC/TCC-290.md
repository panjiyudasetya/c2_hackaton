# [TCC-290] Encounter monitor testing

**URL:** https://teqplaybv.atlassian.net/browse/TCC-290

**Reporter:** Darius Wattimena | **Assignee:** Michel Wilson

**Board:** TCC board  
**Parent:** [TCC-446] Event Monitoring blackbox testing  

## Description

h2. Description

Check in a similar way as we do in the StopMonitor or AreaMonitor. (Black box testing)

Make the testing in such a way so it supports all different type of ship roles. For example, a trace with a pilot ship might result into a  encounter event, but when the service vessels is a bunker it shouldn’t trigger any encounter.

Check for each ship role what the criteria should be to start and end a encounter. Create a document with the findings, so we can use this later when checking if our created tests are giving the correct output.

h2. Test cases from test plan

* Main vessel has lots of AIS point but service vessel has almost no AIS points and ships are laying next to each other
* Service vessel has lots of AIS point but main vessel has almost no AIS points and ships are laying next to each other
* Both ships have lots of AIS points and ships are laying next to each other
* Both ships have almost no AIS points and ships are laying next to each other 
* Main vessel has lots of AIS point but service vessel has almost no AIS points and ships are not laying next to each other
* Service vessel has lots of AIS point but main vessel has almost no AIS points and ships are not laying next to each other
* Both ships have lots of AIS points and ships are not laying next to each other
* Both ships have almost no AIS points and ships are not laying next to each other
* Two service vessels having an encounter with each other should NOT result in a event
* Two main vessels having an encounter with each other should NOT result in a event
* All timestamps start before end time EncounterEvents (Input-output testing)
