# [TCC-441] Fix real time stop location not being classified

## Description

h2. Description

Before we get the StopEndEvent from the StopMonitor there is no way for use to know the actual stop location of the ship, meaning we will end with lots of unclassified stop, even when the ship is clearly laying still in the berth for a long long time.

We do have a berth event from the BerthMonitor which triggers when we are sure the ship stopped inside the berth. We could leverage from this event and improve stop classification when we don’t have the actual stop location yet.

We could also send an intermediate event once we determined the stop actual location after the 2 hour monitoring time that is currently used.

An example case can be seen in the attached screenshot where we stopped before entering the berth, resulting in an unclassified stop. The related Visit → [https://vesselvoyage.teqplay.nl/#/ships/9945849/story/675b90e2-b35c-4f50-87d8-297a9007304f.VISIT?mode=period&months=1|https://vesselvoyage.teqplay.nl/#/ships/9945849/story/675b90e2-b35c-4f50-87d8-297a9007304f.VISIT?mode=period&months=1|smart-link] 

h2. Dependencies

Both in PortReporter and PortcallOne we will show the Berth ATA too late, given that it will only be provided after we provided the StopEndEvent, which is way too late.
