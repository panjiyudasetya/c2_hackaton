# [TCC-1105] Improve AIS jitter filtering so encounter detection can be done easier in SGSIN

**Parent:** [TCC-1051] Reliable bunker encounter events implemented  

## Description

h2. Description

In SGSIN, encounter detection is repeatedly broken by AIS jitter from vessels at anchor. The damaging kind isn't small timing noise — it's *large, sustained bad positions*: a ship's AIS reports it kilometres away at physically impossible speeds, then snaps back. These excursions trip the bunker exit logic and chop a single bunkering into fragments (or drop transfer time).

h2. Why the current jitter defenses miss it

They all hedge in the *time* dimension, never the *space* dimension:

* *Extrapolation* and {{canCatchUp}} trust the reported position — they smooth over timing gaps, they don't question a teleport.
* The *15-min finish timer* absorbs _short_ blips (it saved the WEITEK 18 ~1-min spike), but a long excursion simply outlasts it (37 min > 15 min).

h2. The gap

There is no per-ship *plausibility* check — nothing rejects a fix whose implied speed (distance from the previous fix ÷ elapsed time) is physically impossible, or that contradicts the ship's own reported {{sog}}.

Bunkering should be one encounter (~16:10 → 22:20) but is chopped into two (16:10 → 21:43 and 22:05 → 22:33). Reproduces in isolation. HAI SOON's AIS reports impossible jumps — ~9.5 km implying *28 kn*, then ~5 km implying *81 kn*, while its own {{sog}} reads 7.9 and 0. The bad positions put it 5–12 km away for ~37 min, tripping the bunker exit; a second encounter starts once it's "back" alongside.

# *HAI SOON 16 ↔ NAVIOS CITRINE — 13 July, ~00:00* [https://timelinedev.teqplay.nl/566754000,373046000?URL=https%3A%2F%2Fapidev.teqplay.nl%2Fv0&from=1783879200000&to=1783908000000&selectedTime=1783900886805&selectedEvent=a960ec9d-6886-45e3-8bc7-f747038e2ec1|https://timelinedev.teqplay.nl/566754000,373046000?URL=https%3A%2F%2Fapidev.teqplay.nl%2Fv0&from=1783879200000&to=1783908000000&selectedTime=1783900886805&selectedEvent=a960ec9d-6886-45e3-8bc7-f747038e2ec1]

Heavy jitter from *both* ships.

h2. Fix direction

Drop or hold implausible position jumps — likely upstream at AIS ingestion, or before the encounter exit logic.

Make use of the static information from a ship (to know the length of a ship). Based on this we can make the filter we already have better applying the length of a ship.

Use CSI information to first look what the boundaries should be by using the calculated max speed and the length we already know.

Add a bunch of scenario tests, focused on AIS jittering in SGSIN where we want to improve on. (framework should already be there already) Taking both current jitter cases but also cases which go fine now in SGSIN.

h2. Definition of Done

* Added usecases result in AIS filtered out in the expected way
* Existing AIS testing usecase aren’t changed significantly
* Changes are released
