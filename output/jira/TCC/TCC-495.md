## Description

h2. Description

While implementing the hotfix [https://teqplaybv.atlassian.net/browse/TCC-494|https://teqplaybv.atlassian.net/browse/TCC-494|smart-link], I observed that the ship state has grown to encompass 1.454.942 ships, which is unreasonably large. To further improve performance, devise a mechanism to prune very old ship state entries, both from memory and from the database.

Next to this, investigate whether there is any performance to be gained by parallellizing the actual search function in {{ShipStateSearchService::getByQuery}}.

h2. Scope

* What is part of this change?
** Pruning old ship state in the shared ship state library in ais-engine
** A short experiment in parallellizing {{getByQuery}} to see if performance is to be gained.
* What is not part of this change?

h2. Dependencies

* Does the change have any effect on any of our consumers?
* Does the change have any effect on other components?
