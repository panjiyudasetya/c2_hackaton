## Description

In Rotterdam one of our customers provided feed-back on the following scenario, where DF Montmartre had a slops / swogs vessel alongside, but the encounter seems not detected / reported well.

Situation:

[https://timeline.teqplay.nl/636021310,269057062?from=1751326379000&to=1751430254000&URL=https%3A%2F%2Fapi.teqplay.nl%2Fv0&selectedTime=1751335379018|https://timeline.teqplay.nl/636021310,269057062?from=1751326379000&to=1751430254000&URL=https%3A%2F%2Fapi.teqplay.nl%2Fv0&selectedTime=1751335379018|smart-link] 

Issue was at 1st of July at 4:00. Does work as expected in DEV, but not in LIVE.



----

Findings:

* Ship does seem to be missing an AIS point on LIVE at ~4:04 where on DEV we started the event on the AIS point.
* We missed an AIS point, PROD and DEV should have the same AIS stream?
* Other ships do have data on the berth.
* Both the main ship and service vessel have encounters besides this missed encounter.

Technical questions:

* Do we take into account the heading of the swog barge? Because if that is the case we shouldn’t given that those ships don’t have a compass on board.
* Do we only start encounters if the last point of the main vessel was within 1 hour? Shouldn’t this be higher?



Expectation:

Encounter should’ve been started at {{04:01:03}} given that this is the first AIS point where the encounter with the 2 ships should’ve been possible.

----

DoD:

Fix the issue that we still create the encounter event even when we missed the single AIS point.
