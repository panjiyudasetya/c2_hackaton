## Description

Be able to provide the follwing model:

{noformat}interface ExpectedTimestamps {
  start: string;
  end: string;
}

type AccuracyCheckResult =
  | "ACCURATE"              // The provided timestamps are correct and accurate. Can also mean no timestamps exist when expected.
  | "TIMESTAMP_INACCURATE"; // One of the timestamps is not within expected boundaries.

enum TimestampCategory {
  DRIFTING = "DRIFTING",
  ANCHOR = "ANCHOR",
  PORT = "PORT",
  LOCK = "LOCK",
  TERMINAL = "TERMINAL",
  BERTH = "BERTH",
  PILOT_INBOUND = "PILOT_INBOUND",
  PILOT_OUTBOUND = "PILOT_OUTBOUND",
  TUGS_ARRIVAL = "TUGS_ARRIVAL",
  TUGS_DEPARTURE = "TUGS_DEPARTURE",
  BUNKERS = "BUNKERS"
}

export interface EventEntry {
  id: string;
  activityId?: string | null;
  areaId: string;
  areaName?: string;
  expectedTimestamps?: ExpectedTimestamps;
  reason: AccuracyCheckResult;
}

// Post
{
  visitId: "ASJDOAJSD.VISIT",
  id: 1234512325234,
  activityId: null,
  category: "PORT",
  expectedTimestamps: {
    start: "2025-07-07T18:48:01Z",
    end: "2025-07-07T18:48:01Z"
  }
}

// Delete (Something like this)
v1/deleteExpectedTimestamps/${id}{noformat}

*How to test:*

# Open Time Validator
# Go to the SOF page.
# Press the 3 dots on a category and open the *Time Validator*.
# Creating a new timestamp

* *Scenario 1:* Category has no data.
** Action: Create a new expected timestamp *related to an activity* → should POST and create successfully.
** Action: Create a new expected timestamp *not related to an activity* → should POST and create successfully.
** Expected Result: Status is updated according to the new timestamp ({{valid}}, {{invalid}}, or {{missing}}).

# Updating an existing timestamp

* *Scenario:* Category has an existing timestamp.
** Action: Select an existing timestamp (invalid or missing) and update it → should PUT (update) successfully.
** Expected Result: Status should reflect the updated value.

# Deleting an existing timestamp

* *Scenario 1:* Delete a timestamp *related to an activity* → should DELETE successfully.
* *Scenario 2:* Delete a timestamp *not related to an activity* → should DELETE successfully.
* Expected Result: Status should update to reflect remaining timestamps or “no data” if none left.
