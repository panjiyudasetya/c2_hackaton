## Description

### Description

- Replace all legacy `port_visit_id` generation with `ods_port_visit.visit_id` (the stable canonical PK) across 34 SQL files. Previously, `port_visit_id` was populated as either `concat(ods_port_visit.id, '_', ods_port_visit.visit_id)` (composite) or `ods_port_visit.id` alone (generation_id), both of which are mutable and unstable.
- Stop referencing `fact_port_visit.port_visit_id` from outside the fact_port_visit DML pipeline. All external joins on `fact_port_visit` now use `fact_port_visit.visit_id` (unique-indexed via `idx_fact_port_visit_visit_id_unique`).
- Fix a pre-existing bug in `accuracy/pilot/summary_accuracy.sql` where `fact_pilot` was joined to `fact_port_visit` on `.id` (the raw generation_id column) instead of `.visit_id`.

### Scope

**Fact DML pipeline** (anchor, bunkering, tug, pilot, ship_to_ship, port_visit):
- `proceed.sql` / `proceed_delta.sql` for anchor, bunkering, tug, pilot, ship_to_ship: `pv.id` or `concat(pv.id, '_', pv.visit_id)` replaced with `pv.visit_id`
- All `prepare_*.sql` files in `port_visit/`: internal CTE routing keys (`bpv.id`) replaced with `bpv.visit_id`
- `add_berths_summary`, `add_terminals_summary`, `add_shifting_inside_terminals`, `add_ship_to_ship_summary`: post-ETL UPDATE steps now route by `visit_id`

**Quality control** (11 files): accuracy components for anchor, bunkering, tug, pilot, port_visit; completeness encounter pilot; validity anchor overlaps

**Silver + analytics** (3 files): `enriched_portcall_performance_monthly`, `calculate_outlier_flags`, `update_port_visit_from_temp`

### What is intentionally preserved

- `ON pv.id = opv.id` joins within ODS-level CTEs (e.g. `pilot_components.sql`, `prepare_ods_encounter_pilot.sql`) are intentional ODS self-joins by generation_id and must not change.
- `ON pv.id = inb.port_visit_gen_id` lines in `pilot/proceed.sql` join on `port_visit_gen_id`, a dedicated column that explicitly holds generation_id for internal temp-table routing.
- `fact_port_visit.port_visit_id` column is retained in the schema. After data migration it equals `visit_id` and is written only by the `proceed.sql` pipeline.

### Post-deployment step (one-time, run manually)

Run the migration script to normalize existing rows in all fact tables. The script is idempotent and wrapped in a single transaction.

<summary>Migration SQL</summary>

```sql
-- Data migration: normalize port_visit_id to visit_id across all fact tables.
--
-- Background:
--   fact_port_visit.port_visit_id was historically populated with either:
--     (a) concat(ods_port_visit.id, '_', ods_port_visit.visit_id)   -- composite legacy format
--     (b) ods_port_visit.id                                         -- generation_id only
--   After this migration, all tables hold ods_port_visit.visit_id (the stable canonical PK).
--
-- After migration:
--   fact_port_visit.port_visit_id is retained in the schema but equals visit_id.
--   It is written only by the fact_port_visit DML pipeline (proceed.sql) and must
--   not be used as a foreign key reference by any other table or query — use
--   fact_port_visit.visit_id instead (indexed by idx_fact_port_visit_visit_id_unique).
--   TODO: drop fact_port_visit.port_visit_id once all downstream BI/external consumers
--         have been confirmed to use visit_id.
--
-- Safe to run multiple times (idempotent WHERE clauses).
-- Run BEFORE deploying updated DML templates.
-- Execute in a single transaction; roll back if any validation step fails.

-- =============================================================================
-- PRE-MIGRATION VALIDATION
-- =============================================================================

-- 1a. Count fact_port_visit rows that still have the composite legacy ID.
SELECT count(*) AS fact_port_visit_composite_legacy
FROM fact_port_visit
WHERE port_visit_id LIKE '%_%' AND port_visit_id != visit_id;

-- 1b. Count fact_anchor rows whose port_visit_id matches ods_port_visit.id (generation_id).
SELECT count(*) AS fact_anchor_generation_id_legacy
FROM fact_anchor AS fa
INNER JOIN ods_port_visit AS opv
    ON fa.port_visit_id = opv.id
WHERE fa.port_visit_id != opv.visit_id;

-- 1c. Same for fact_bunkering.
SELECT count(*) AS fact_bunkering_generation_id_legacy
FROM fact_bunkering AS fb
INNER JOIN ods_port_visit AS opv
    ON fb.port_visit_id = opv.id
WHERE fb.port_visit_id != opv.visit_id;

-- 1d. Same for fact_tug.
SELECT count(*) AS fact_tug_generation_id_legacy
FROM fact_tug AS ft
INNER JOIN ods_port_visit AS opv
    ON ft.port_visit_id = opv.id
WHERE ft.port_visit_id != opv.visit_id;

-- 1e. Same for fact_pilot.
SELECT count(*) AS fact_pilot_generation_id_legacy
FROM fact_pilot AS fp
INNER JOIN ods_port_visit AS opv
    ON fp.port_visit_id = opv.id
WHERE fp.port_visit_id != opv.visit_id;

-- 1f. Count fact_ship_to_ship_transfers rows with the composite legacy ID.
--     (These reference the old fact_port_visit.port_visit_id value, not ods_port_visit directly.)
SELECT count(*) AS fact_ship_to_ship_composite_legacy
FROM fact_ship_to_ship_transfers AS fssts
INNER JOIN fact_port_visit AS fpv
    ON fssts.port_visit_id = fpv.port_visit_id
WHERE fssts.port_visit_id != fpv.visit_id;

-- =============================================================================
-- MIGRATION
-- NOTE: fact_ship_to_ship_transfers MUST be migrated BEFORE fact_port_visit
--       because it joins on the current (pre-migration) fact_port_visit.port_visit_id.
-- =============================================================================

BEGIN;

-- Step 1: fact_ship_to_ship_transfers — join on current fact_port_visit.port_visit_id
--         to find the corresponding visit_id before fact_port_visit is updated.
UPDATE fact_ship_to_ship_transfers AS fssts
SET port_visit_id = fpv.visit_id
FROM fact_port_visit AS fpv
WHERE fssts.port_visit_id = fpv.port_visit_id
  AND fssts.port_visit_id != fpv.visit_id;

-- Step 2: fact_port_visit — set port_visit_id = visit_id (PK update; safe because
--         no child table has a FK pointing to fact_port_visit.port_visit_id).
UPDATE fact_port_visit
SET port_visit_id = visit_id
WHERE port_visit_id != visit_id;

-- Step 3: fact_anchor — resolve generation_id to visit_id via ods_port_visit.
UPDATE fact_anchor AS fa
SET port_visit_id = opv.visit_id
FROM ods_port_visit AS opv
WHERE fa.port_visit_id = opv.id AND fa.port_visit_id != opv.visit_id;

-- Step 4: fact_bunkering.
UPDATE fact_bunkering AS fb
SET port_visit_id = opv.visit_id
FROM ods_port_visit AS opv
WHERE fb.port_visit_id = opv.id AND fb.port_visit_id != opv.visit_id;

-- Step 5: fact_tug.
UPDATE fact_tug AS ft
SET port_visit_id = opv.visit_id
FROM ods_port_visit AS opv
WHERE ft.port_visit_id = opv.id AND ft.port_visit_id != opv.visit_id;

-- Step 6: fact_pilot — update port_visit_id.
UPDATE fact_pilot AS fp
SET port_visit_id = opv.visit_id
FROM ods_port_visit AS opv
WHERE fp.port_visit_id = opv.id AND fp.port_visit_id != opv.visit_id;

-- Step 6b: recompute fact_pilot.id after port_visit_id has been normalised.
-- fact_pilot.id = md5(concat(port_visit_id, port_unlocode, visit_id, ...)), so changing
-- port_visit_id invalidates the PK hash for every pre-migration row. pilot_components.sql
-- computes the same hash and summary_accuracy.sql joins on it; stale hashes cause a
-- full accuracy miss until this step runs.
UPDATE fact_pilot AS fp
SET
    id = md5(concat(
        fp.port_visit_id
        , fp.port_unlocode
        , fp.visit_id
        , fp.vessel_ship_id
        , fp.service_ship_imo
        , fp.service_ship_mmsi
        , fp.timestamp
        , fp.fallback_type
        , fp."type"
    ))
WHERE fp.id != md5(concat(
    fp.port_visit_id
    , fp.port_unlocode
    , fp.visit_id
    , fp.vessel_ship_id
    , fp.service_ship_imo
    , fp.service_ship_mmsi
    , fp.timestamp
    , fp.fallback_type
    , fp."type"
));

COMMIT;

-- =============================================================================
-- POST-MIGRATION VALIDATION — all counts should be 0 after successful migration.
-- =============================================================================

-- 2a. fact_port_visit: no composite or legacy IDs should remain.
SELECT count(*) AS fact_port_visit_remaining_legacy
FROM fact_port_visit
WHERE port_visit_id != visit_id;

-- 2b. fact_anchor: no rows should reference a generation_id that differs from visit_id.
SELECT count(*) AS fact_anchor_remaining_legacy
FROM fact_anchor AS fa
INNER JOIN ods_port_visit AS opv
    ON fa.port_visit_id = opv.id
WHERE fa.port_visit_id != opv.visit_id;

-- 2c. fact_bunkering.
SELECT count(*) AS fact_bunkering_remaining_legacy
FROM fact_bunkering AS fb
INNER JOIN ods_port_visit AS opv
    ON fb.port_visit_id = opv.id
WHERE fb.port_visit_id != opv.visit_id;

-- 2d. fact_tug.
SELECT count(*) AS fact_tug_remaining_legacy
FROM fact_tug AS ft
INNER JOIN ods_port_visit AS opv
    ON ft.port_visit_id = opv.id
WHERE ft.port_visit_id != opv.visit_id;

-- 2e. fact_pilot: port_visit_id normalised.
SELECT count(*) AS fact_pilot_remaining_legacy
FROM fact_pilot AS fp
INNER JOIN ods_port_visit AS opv
    ON fp.port_visit_id = opv.id
WHERE fp.port_visit_id != opv.visit_id;

-- 2e2. fact_pilot: id hash recomputed (stale hashes break summary_accuracy join).
SELECT count(*) AS fact_pilot_stale_id_hash
FROM fact_pilot AS fp
WHERE fp.id != md5(concat(
    fp.port_visit_id
    , fp.port_unlocode
    , fp.visit_id
    , fp.vessel_ship_id
    , fp.service_ship_imo
    , fp.service_ship_mmsi
    , fp.timestamp
    , fp.fallback_type
    , fp."type"
));

-- 2f. fact_ship_to_ship_transfers: all port_visit_id values should now exist in
--     fact_port_visit as visit_id (the canonical PK index).
SELECT count(*) AS fact_ship_to_ship_orphaned
FROM fact_ship_to_ship_transfers AS fssts
LEFT JOIN fact_port_visit AS fpv
    ON fssts.port_visit_id = fpv.visit_id
WHERE fpv.visit_id IS null;

```

</details>

Order matters: `fact_ship_to_ship_transfers` must be updated before `fact_port_visit` because it resolves the mapping via the current (pre-migration) `fact_port_visit.port_visit_id` value.
