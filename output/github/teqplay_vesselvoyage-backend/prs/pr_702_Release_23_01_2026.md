## Pull request overview

This release refines post-processing resilience, HTTP client robustness, and API models around visits and pagination, adding better observability and handling for failure scenarios.

**Changes:**
- Extended `PostProcessingService` with more robust thread pool timeout handling, including secondary timeouts, forced executor recreation, and additional Slack alerts (with a new yellow Slack color).
- Tightened external HTTP client behavior by configuring connection and read timeouts for DriftPredictor and Auth0 `RestTemplate`s.
- Generalized paginated API visit responses from `ImoVisit` to `ApiVisit` and adjusted mapping and controller logic accordingly.

The new timeout and recovery flow around `handleThreadPoolTimeout` / `waitForActiveThreadsToComplete` / `forceTerminateAndRecreateExecutor` introduces non-trivial behaviour (secondary timeouts, Slack notifications, executor shutdown and recreation), but there are no unit tests covering these paths, while `PostProcessingService` has extensive tests for other behaviours. Please add targeted tests that simulate a non-empty `ThreadPoolTaskExecutor` (e.g. using a small pool and blocking tasks) to verify: (1) we log and send the expected Slack messages on primary and secondary timeouts, (2) pending tasks are drained via `cancelPendingTasks`, (3) the old executor is shut down and a new one created, and (4) subsequent cycles can successfully submit work to the recreated executor.
