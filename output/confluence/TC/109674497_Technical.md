## Invoice Decision Tree:

The following flowchart gives an idea of how a portcall is invoiced to a particular company. Currently an invoice is generated for Agency and ShippingCompany. Please note that, this flowchart only gives an idea of how a portcall is grouped/categorised by a Company. It does not show how the prices are picked. ## Blacklisting ShippingLines on Agencies when invoicing portcalls

To exclude portcalls to be invoiced based on the portcall's Agency and ShippingLine, the config variable **addonFeature.portcallOrderBlackList** can be used.

This variable contains a **map<String,List\<String>>** **in Json format** in which the key represents an AgencyId and the value a list of ShippingLineIds.

**Note that** the String delimiter must be ' instead of " to avoid problems when reading the properties.

# Invoice options

Invoices are generated by a spring cron job, defined at: Invoicing -> scheduledInvoicing() every Wednesday for the previous week. Invoices are generated based on the following invoice configuration options: (\*) are mandatory options

#!python
invoice.cycle=<int> (\*): Invoicing cycle duration in days
invoice.dueDays=<int> (\*): Invoicing due date to pay the bills
invoice.agents=["<agencyName1>",..., "<agencyNameN>"] : Optional list if filled in, only these agencies will be invoiced. Rest of the agencies will be ignored.
invoice.options={"<port1>":["invoiceOptions1",..., "invoiceOptionsN"], "<port2>":["invoiceOptions1",..., "invoiceOptionsN"]} (\*): Invoice options per port. Different options are:
- COLLATED\_INVOICE: Creates an invoice (with a unique invoice number) for all the portcalls.
- COLLATED\_REFERENCE: Creates a collation of all portcall invoices. This will generate a unique reference number (not an invoice number.
- COLLATED\_CREDIT\_REFERENCE: Creates a collation of all portcall credit references. This will generate a unique reference number.
- PORTCALL\_INVOICE: Creates an invoice of individual portcalls each having a unique invoice number
- PORTCALL\_REFERENCE: Gives details of a particular portcall. This will generate a unique reference number (not an invoice number
- PORTCALL\_CREDIT: Create a credit invoice (with a unique invoice number) for a portcall. This is Discount given to the port.
invoice.price={"<port1>": "<priceType>"} (\*): The price per portcall reporting service. For Rotterdam, its based on the Dry Weight Tonnage. Types are:
- "150" or any number, actual price per unit of service.
- "DWT": Costs based on the Dry Weight Tonnage of the vessel. Not implemented yet
invoice.credit={"<port1>": <negativeIntOrZero>, "port2": <negativeIntOrZero>} (\*): The credits given to a specific port as a rebate/discount for using our services. Mandatory field if the invoice option is PORTCALL\_CREDIT.
invoice.vat=<int> (\*): The percentage vat that has to be applied to the overall portreporting costs
invoice.defaultEmail=["email1", "email2"]: Every invoice is sent specifically to the agency invoiceEmail. A copy will also be sent to this list

Users with ADMIN rights can also generate (new) and regenerate (update) invoices. The following endpoints can be used:

Regenerate an invoice based on a given invoice ids and email it to the given list. This fetches the given invoice and updates the agency and the shipping line details.

#!php
POST /invoices#!json
{
"invoiceIds" : ["<invoiceId1>", ..., "<invoiceIdN>"],
"email" : ["<emailAddress1>", ..., "<emailAddressN>"]
}

Regenerate an invoice for a specific list of portcalls and email it to the given list. Important thing to note is that this is fetch the most recent invoice for the given portcall and updates the agency and the shipping line details.

#!php
POST /invoices/byPortcall#!json
{
"portcallIds" : ["<portcallId1>", ..., "<portcallIdN>"],
"email" : ["<emailAddress1>", ..., "<emailAddressN>"]
}

Generate a new invoice based on a given invoice option (refer to table above) for a specific list of portcalls and email it to the given list. This will create a new invoice "entry" in the db.

#!php
POST /invoices/generateNew#!json
{
"portcallIds" : ["<portcallId1>", ..., "<portcallIdN>"],
"email" : ["<emailAddress1>", ..., "<emailAddressN>"],
"invoiceOptions" : ["<invoiceOption1>", ..., "<invoiceOptionsN>"]
}

The automated cycle of invoicing can be forced by an ADMIN user. All invoice related options/data is picked from the config. This will create a new invoice "entry" in the db.

#!php
POST /invoices/triggerInvoiceCycle

# Subscription CRUD

Fetch all subscriptions for an particular userId:

#!php
GET /subscriptions/{userId}?portcallId=<portcallId>

Filter a specific subscription:

#!php
GET /subscriptions/{uuid}

Create a subscription

#!php
POST /subscriptions#!json
{
"userId" : "<userId>",
"portcallId" : <portCallId>,
"details" : [{
"portCallEventType" : "<eventType e.g. PORT\_ETA\_AGENT>",
"eventTypeCategory" : "<INBOUND, ALONGSIDE, SHIFTING, OUTBOUND>"
"medium" : [CALL, SMS, EMAIL, PUSH]
}]
}

Delete a subscription

#!php
DELETE /subscriptions/{uuid}

Update a subscription

#!php
PATCH /subscriptions/{uuid}
{
<updateJSON>
}

Update the subscription details alone. Keeping the medium empty will unsubscribe itself.

#!php
PATCH /subscriptions/{uuid}/details
{
"portCallEventType" : "<eventType e.g. PORT\_ETA\_AGENT>",
"eventTypeCategory" : "<INBOUND, ALONGSIDE, SHIFTING, OUTBOUND>"
"medium" : [CALL, SMS, EMAIL, PUSH]
}
