# Cert-manager for auto creating TLS certificates

**Space:** TC  
**URL:** https://teqplaybv.atlassian.net/wiki/spaces/TC/pages/742588417  

## Content

The application leverages cert-manager to automate the creation and renewal of TLS certificates for the RabbitMQ clusters. This ensures secure communication without manual intervention. You can find more information on cert-manager at its official documentation site <https://cert-manager.io/docs/>.

## Install

Add repository

helm repo add jetstack https://charts.jetstack.io --force-update

Install Helm chart

helm install \
cert-manager jetstack/cert-manager \
--namespace cert-manager \
--create-namespace \
--version v1.17.2 \
--set crds.enabled=true

Check the cert-manager

kubectl -n cert-manager get all
kubectl explain Certificate
kubectl explain CertificateRequest
kubectl explain Issuer

## Setup cert-manager with Route53

<https://cert-manager.io/docs/configuration/acme/dns01/route53/>

Create an IAM policy `TeqplayCertManagerPolicy`, which allows `cert-manager` to have access to Route53. An important permission is to allow `cert-manager` to change a DNS record in a specific hosted zone.

**Policy**

json{
"Version": "2012-10-17",
"Statement": [
{
"Effect": "Allow",
"Action": "route53:GetChange",
"Resource": "arn:aws:route53:::change/\*"
},
{
"Effect": "Allow",
"Action": [
"route53:ChangeResourceRecordSets",
"route53:ListResourceRecordSets"
],
"Resource": "arn:aws:route53:::hostedzone/Z038052928XYZU4SNK9G5",
"Condition": {
"ForAllValues:StringEquals": {
"route53:ChangeResourceRecordSetsRecordTypes": [
"TXT"
]
}
}
},
{
"Effect": "Allow",
"Action": "route53:ListHostedZonesByName",
"Resource": "\*"
}
]
}

In this example resource `arn:aws:route53:::hostedzone/Z038052928XYZU4SNK9G5` is the `arn` for domain `dev.teqplay.com`.

### Create IAM role

The IAM role will be mapped to the service account `cert-manager`. First get the OIDC provider ID. See picture below how to get that information.

#### Step 1

Go to IAM roles and create a new IAM role.

#### Step 2

Go to the next step and add the policy `TeqplayCertManagerPolicy`.

#### Step 3

Rename the IAM role to TeqplayRoleCertManager. Establish the trust relationships as shown in the example below, replacing [oidc.eks.eu-west-1.amazonaws.com/id/5FC7B8323EF5BB6AA9FB5B0CC8D2D827] with your actual EKS cluster oidc name.

#### Trust relationships

{
"Version": "2012-10-17",
"Statement": [
{
"Effect": "Allow",
"Principal": {
"Federated": "arn:aws:iam::050356841556:oidc-provider/oidc.eks.eu-west-1.amazonaws.com/id/5FC7B8323EF5BB6AA9FB5B0CC8D2D827"
},
"Action": "sts:AssumeRoleWithWebIdentity",
"Condition": {
"StringEquals": {
"oidc.eks.eu-west-1.amazonaws.com/id/5FC7B8323EF5BB6AA9FB5B0CC8D2D827:sub": "system:serviceaccount:cert-manager:cert-manager",

## Cluster issuer

Create a cluster issuer.

yamlapiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
name: letsencrypt-dev
spec:
acme:
server: https://acme-v02.api.letsencrypt.org/directory
privateKeySecretRef:
name: letsencrypt-dev-private-key
solvers:
- dns01:
route53:
region: eu-west-1
hostedZoneID: Z038052928XYZU4SNK9G5

The name and privateKeySecretRef values are configurable based on the environment. For production deployments, `dev` can be omitted.

## Certificate

Create a certificate for domain `rabbitmq.dev.teqplay.com`.

bashkubectl apply -f - <<EOF
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
name: rabbitmq-certificate
namespace: brokers
spec:
secretName: rabbitmq-tls-secret
issuerRef:
name: letsencrypt-dev
kind: ClusterIssuer
dnsNames:
- rabbitmq.dev.teqplay.com
EOF

To validate your domain for a new certificate, cert-manager will create a DNS record within your hosted zone. This record allows `Let's Encrypt` to verify domain ownership.

## Changes to RabbitMq cluster

The existing TLS secret is replaced by the one generated by Let's Encrypt. For this to work, set `existingSecretFullChain` to `true`.

auth:
existingPasswordSecret: rabbitmq-password-dev
tls:
enabled: true
existingSecret: rabbitmq-tls-secret
existingSecretFullChain: true
failIfNoPeerCert: false
sslOptionsVerify: verify\_none

## Test RabbitMq cluster certificate

Let's Encrypt renews certificates automatically every couple of months. To test this, use the following code:

kubectl exec -n brokers -it rabbitmq-cluster-0 -c rabbitmq -- /bin/shopenssl s\_client -connect localhost:5671 -showcerts
