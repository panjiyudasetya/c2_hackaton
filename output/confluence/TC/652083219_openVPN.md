# openVPN

## Content

# Server

On `vpn.teqplay.nl`, an OpenVPN server is installed for access to the Amazon private VPC. The VPN server allocates IP addresses out of the 192.168.200.0/24 block. Src/dst checks are disabled on the instance, to allow the server to generate traffic out of this block, and a route for this block to the VPN server is added in the VPC management route tables.

For DNS/name resolution, `dnsmasq` is installed, which is a very basic forwarding name server. This server listens on the VPN virtual network interface, and forwards DNS queries to the Amazon name servers. This allows resolution of records in the private DNS zones in Route 53 (for example, for `dbpronto.teqplay`), and it ensures that private IP addresses are returned for queries in our VPC (for example, for `backend.teqplay.nl`).

Certificates are used for authentication, generated using a private CA certificate. For this, the `easy-rsa` wrapper scripts around `openssl` are used, the CA is installed in `~/CA`. A server certificate is used for the VPN server, and client certificates are used for the clients. If you want to create a new client certificate, execute the following steps:

* `cd ~/CA`
* `source vars`
* `./build-key <username>`
* For the username I generally use `firstname_lastname`, and `firstname_lastname-devicetype`, to distinguish certificates from each other
* For the "Common Name" enter the full name of the user, for the "Email Address" enter the Teqplay email address, accept all the other defaults as given, answer `y` to the two final questions
* The certificate files are now saved in `~/CA/keys/<username>.{crt,csr,key}`

To make an OpenVPN configuration file (a `.ovpn` file) which can be imported in the client, the `gen_ovpn.sh` script can be used:

* For Linux machines: `./gen_ovpn.sh <username> > ~/<username>.ovpn`
* For Windows machines: `./gen_ovpn.sh -w <username> > ~/<username>.ovpn`

The `-w` options omits `up`/`down` scripts that configure DNS for Linux machines.

Next, transfer the `.ovpn` file *in a secure way* to the user. LastPass secure notes are a good option for this, or just `scp` for Linux machines. Then, the `.ovpn` file can be deleted on the server.

# Windows clients

Download the client software [here](https://openvpn.net/community-downloads/) and install it. Import the `.ovpn` file (first rename it to `teqplay.ovpn` to give the connection a recognizable name), and start the connection. Should work out of the box! The only challenge can be finding the icon in the systray, it is almost identical to the Windows network connections icon!

If you encounter DNS issues, i.e., hostnames are not resolved to their internal IP addresses, give these extra options a try (you can add them to the `.ovpn` configuration file):

* `register-dns`
* and if that doesn't work: `block-outside-dns`

# Mac clients

* Install OpenVPN Connect GUI from [here](https://openvpn.net/client-connect-vpn-for-mac-os/)
* Import `your.ovpn` file into the app
* Ready to go!

# Linux clients (Debian, Ubuntu)

Install the packages `openvpn` and `network-manager-openvpn-gnome`. On Ubuntu, also install `resolvconf` if not already installed. Also, on Ubuntu, add the following lines to the `[main]` section of `/etc/NetworkManager/NetworkManager.conf`:

wide760rc-manager=resolvconf
dns=default

Then, restart NetworkManager by doing a `systemctl restart NetworkManager`.

Get the `.ovpn` file on your machine, optionally renamed to `teqplay.ovpn` to give the connection a more descriptive name. Click on the network manager icon, select "VPN Connections", "Configure VPN...". Click "Add", select "Import a saved VPN Configuration...", click "Create..." and select the `.ovpn` file. After importing the file, open the "Configure VPN..." dialog again, edit the imported connection. Go to "IPv4 Settings", click "Routes..." and ensure that automatically obtained routes are not ignored, and that the connection is used only for resources on its network. Then, bring the connection up, and everything should work.

> Alternatively, the teqplay.ovpn file can also be imported via the command line:
>
> sudo nmcli connection import type openvpn file /path/to/teqplay.ovpn

# Revoke (disable) a certificate

Use AWS SSM to login into the machine

wide760aws ssm start-session --target i-019aed679e95bbad9 --profile dev

You will enter a layer between AWS and the machine. Use this command to login as `ubuntu` user:

wide760sudo -i -u ubuntu

Now, go to the `EasyRSA-2.2.2` folder and initialize your environment:

wide760cd CA
source vars

If needed, lookup the key file name in `~/CA/keys`. Then, revoke the certificate and update the certificate revocation list:

wide760./revoke-full <keyname>
sudo cp keys/crl.pem /etc/openvpn/

The `revoke-full` command should output an error of the form `error <keyname>.crt: verification failed`, this is expected, and confirms that the certificate of that name is successfully revoked. A restart of the OpenVPN server is not needed.
