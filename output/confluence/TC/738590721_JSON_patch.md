## What is JSON Patch?

JSON Patch is a list of operations, each with the following structure:

* `add`
* `remove`
* `replace`
* `move`
* `copy`
* `test`

Pros

* **Efficient Updates**: Sends only the changes, not the full document — reducing payload size.
* **Fine-Grained Control**: Enables precise targeting of specific fields within complex structures.
* **Useful for APIs**: Ideal for PATCH requests in RESTful APIs to update resources partially.

Cons

* **Complexity for Simple Changes**: Overkill if you only need to update a single value.
* **Not Human-Friendly**: Can be harder to read and write manually compared to full JSON.
* **Error-Prone**: Paths must be exact; a missing key or incorrect path leads to failure.
* **No Schema Awareness**: Doesn’t validate against a schema .
* **Limited Debugging**: Troubleshooting multi-op patches can be challenging.

### Examples

1. Replace the age

`{ "name": "Alice", "age": 30 }`

That would look something like this

[
{ "op": "replace", "path": "/age", "value": 31 }
]

2. Add a new field:

[
{ "op": "add", "path": "/email", "value": "alice@example.com" }
]

3. Remove a field:

[
{ "op": "remove", "path": "/age" }
]

…   
Let’s say we want to change both the name and the age it would look something like this:

[
{ "op": "replace", "path": "/name", "value": "Alicia" },
{ "op": "replace", "path": "/age", "value": 34 }
]

The nice things with JSON patch from this examples is that:

* **Saves Bandwidth**: Instead of sending the entire file or object, you only send the small parts that changed. This makes things faster and uses less data.
* **Smaller Updates**: You can change just one piece of data (like a single field) without touching the rest. This is great for large or complex data.
* **Clear Actions**: Each patch shows exactly what you want to do — like “add this,” “remove that,” or “change this value.” It’s easy to see what’s happening.
* **All-or-Nothing**: If something in the patch is wrong, nothing changes. This helps prevent broken or incomplete updates.
* **Works Everywhere**: JSON Patch follows a standard that many tools and languages support. That makes it easy to use across different systems.
* **Good for Tracking Changes**: You can save patches as a history of changes — kind of like how version control systems (like Git) work. This helps with undoing changes or reviewing what was changed.

### When JSON Patch Might Be Overkill?

While JSON Patch is powerful, it's not always the right tool for every project.

In many cases, especially smaller projects or simple APIs using JSON Patch can feel like **too much complexity for not enough benefit**. Here’s why:

* **You need to track the original state**: To create a patch, you must know exactly what changed. That means comparing the new version with the old one, which adds extra work. (They are some libaries like) `fast-json-patch`

* **Simple changes can be simpler without it**: If you're just updating a few fields, it might be easier and more readable to send the full updated JSON or use a custom object with only the fields you want to change.
