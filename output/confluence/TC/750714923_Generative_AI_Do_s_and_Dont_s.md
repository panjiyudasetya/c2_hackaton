# Generative AI Do's and Dont's

**Space:** TC  
**URL:** https://teqplaybv.atlassian.net/wiki/spaces/TC/pages/750714923  

## Content

**Use cases**

Summary of lessons learned on Do’s and Dont’s from experiences of the GenAI experiment, denoting what the team thinks should be delegated and shouldn’t be. Feel free to add any missing items but be sure to discuss with the Team first.

## ✅ Should be delegated

* Routine coding tasks (CSS, boilerplate setup, basic CRUD)
* Automated testing
* Repetitive tasks (e.g., automated notifications on failures)
* Drafting and improving documentation
* Supporting professional writing (assistance, not replacement)
* Initial problem-solving and troubleshooting
* Providing learning curriculums or roadmaps
* Rapid domain familiarization
* Assisting in daily technical coding tasks
* Code reviews (recommended 50/50 AI-human split for optimal quality)
* Explaining detailed code segments clearly
* Facilitating brainstorming processes
* Copiloting development tasks (human-AI role interchange)

---

## ❌ Should not be delegated

* High-level systems and architectural design decisions
* Final reviews and approvals (always require human oversight)
* Independent authoring of critical texts and documentation (including creating/reviewing important code/documentation)
* Clearly defining requirements and architectural specifications
* Codebase-wide standardization decisions
* Final design system decisions (brand identity, UI/UX principles)
* Critical business logic, including roles and permissions (AI may assist but not decide)
* Complex code changes affecting multiple codebase areas
* Unsupervised code fixes
* Tasks assigned to inexperienced developers in early learning stages
* Decision making on how to apply or integrate AI itself (AI can suggest but not decide)
* Making decisions without human supervision
