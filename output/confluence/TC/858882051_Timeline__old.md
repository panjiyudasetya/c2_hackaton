# Introduction

This document describes the Timeline project, which started in 2019 as a graduation project of Damon Asberg. It has grown into a fully fledged debugging tool used daily in Teqplay.

<https://github.com/teqplay/timeline>

**Timeline** is a vessel tracking and analysis tool for visualizing ship movements, events, and timelines. It provides a map-based interface, interactive timeline, and advanced filtering for maritime data, supporting import/export and multi-server authentication.

# Key features

* **Internal usage within Teqplay only**
* Playback and view a replay vessel movements over time
* Visualise ship positions, routes and events on an interactive map
* Analyse the history of vessels using events and a powerful Timeline
* Analyse the history of multiple vessels at the same time

# How to use

## Direct URL linking

The main use case of this Timeline is by supplying a direct URL from another tool to this tool. The way this works is because the Timeline has a fixed URL which can be filled in by other tools easily:

https://timeline.teqplay.nl/`MMSI,MMSI,MMSI`?from=`UNIX_FROM`&to=`UNIX_TO`&URL=`SERVER_URL`

The MMSI,MMSI,MMSI can be replaced with any valid MMSI (or TeqplayID if the SERVER\_URL supports it). Example is `353136000`. **IMO numbers are not valid for this tool.**

The `UNIX_FROM` and `UNIX_TO` can be replaced with any valid UNIX timestamps. Valid example is `1757420236915`. **ISO 8601 timestamps are not supported.**

Server URL can be filled to directly target a specific server, such as **https://api.teqplay.nl/v0**.

## Using the tool to look up

Inside the tool there is also a search bar in which you can search for any particular vessel using its name, MMSI or IMO number. In the top right of the tool a specific date range can be selected, or you can click on the shortcut buttons for the past hour or past 24 hours to be viewed.

## Data retrieved

The tool works by retrieving data of vessels within a specific time frame. For this time frame we retrieve the following data:

* AIS history

  + These are **all** received AIS data points that have been transmitted by the vessel.
  + Using these points we can create a trace / line of where the vessel has been
* Ship events

  + **Events** are generated by the platform / backend of Teqplay, which are all derived from AIS data points. An example of events are location based events, which have an Arrived and Departed event for when a ship enters a specific boundary marked as a location.
  + **Composed events** are singular events grouped together for ease of use.
* Static ship infomation

  + These are the Ships' particulars and static information, which includes info such as the width, height, MMSI, IMO, Ship Type and many other information types.
  + This is retrieved from our CSI system.
* Relevant ships

  + **Relevant ships** are determined using Events, mainly Encounter events with another vessel. These events will contain information such as an MMSI or IMO number of another ship. For display purposes, whenever such an event occurs the Timeline will fetch the following information for each Relevant ship:

    - AIS history between relevant timeframe (15 min before encounter start or timeframe start, until 15 min after encounter ends or timeframe ends)
    - Static ship information
* Portcall information

  + An optional fetch can be done for Portcall information, some events will contain UCRN codes which correlate to a Portcall identifier for the Port Reporter system. Additional information can be fetched from the Port Reporter system to be displayed in the Timeline.

## Playback functionality

Using the buttons in the top right of the application, you can control the playback of the Timeline. The buttons have the following functionality (left to right):

* Current time of playback

  + When clicked, it will show you a menu to show all timestamps in another timezone of your choice.
* Slow playback down (⏪)
* Speed playback up (⏩)
* Go to first AIS data point (|<)
* Go back 1 AIS data point (◀️)
* Play / stop playback ( / )
* Go forwards 1 AIS data point (▶️)
* Go to last AIS data point (>|)
* Flip playback direction

  + When clicked, it will change the direction the playback is, from forwards to backwards vice/versa.
* Keyboard shortcuts ( ? )

## Timeline and map interaction

### Analysis of data / event data

Every time a ship has events, they will be displayed on the left hand side in the event list tab. When clicking on an event, all the details of the events will be shown. The event list has several options at the bottom; You can resize the events to a different size, between `Large` and `Condensed`. You can also change the sort, from `Newest first` to `Oldest first`. There is also an elaborate event filtering available.

#### Filtering events

The event filtering mechanism allows you to filter out (or in) certain types of events. This can be useful in situations where you have so many events you cannot find the one you want to see. **These event filterings will also be applied on the events visible on the map, and on the Timeline at the bottom of the screen.**

#### Event details

Once clicked on an event, different details will be shown to you depending on the information available. The raw JSON can also be viewed by clicking the button in the bottom `</>`.

### Map layers

* AIS vessels in radius

Inside the layers menu, this layer can be activated by pressing the left button. You can customize the radius around the vessel (in meters, max 500m) how far away you want to see vessels. The filter button allows you to filter out certain ship roles or ship types.

* AIS vessels in custom area

This layer can be activated in similar fashion to the AIS vessels in radius layer by pressing the left area of the button. When clicked / activated, click anywhere on the map to get an initial area to see AIS vessels for. When this is placed, the edges of the area can be moved as you desire.

* Area layers (anchor, berths, terminals etc)
* Elements such as bridges, bollards, buoys, locks

### Map backgrounds

There are 4 different map backgrounds: default / light, ECDIS coloured, OpenStreetMaps and Mapbox Satellite view.

There is an optional <https://map.openseamap.org/> background inside the elements list which contains more detailed information about ports.

# Customisation and tweaking

* Showing ship contours up close

  + When zoomed in to a certain level, the default arrow icon for ships get replaced by the actual contours of the vessel as given by its AIS signal.
* Showing ship label

  + Show the ship name / MMSI or hide it
* Showing trace on/off

  + Useful for when the AIS trace is very cluttered in a certain area
* Color trace based on index, speed, AIS course
* Decluttering map items

  + This feature is useful for when a ship trace is cluttered in a specific area, and you only want to see x minutes before and after the selected time. Edit the `Declutter time` for this.
* Toggle low accuracy data

  + Sets `revalidate` inside any `/v0/ship/history` endpoints. When toggled on, set to `true` otherwise `false`.
* Toggle non chronological AIS points

  + Because we use multiple AIS sources if available, it might be possible that an AIS data point will be received and processed earlier than another point which happened earlier - but processed later. This frequently happens with multiple mixed sources i.e. Satellite AIS and Terrestrial AIS.
  + This is completely done inside the front-end and not sent to the backend.
* Dutch/English language
* Toggle to display AIS source in Timeline
* Toggle for relevant ships
* Toggle for portcall information
* Toggle for interpolation of data points

  + By default, it will interpolate the ship location between data points relative to the selected time of the Timeline. If disabled, it will show the ship at the latest known location before the selected time.
* Toggle AIS lost
* Toggle showing eventTime instead of dateTime

  + This relates to the time and date displayed inside the Event list on the left side of the Timeline. The eventTime property is the time when the event happened, the datetime is the time the backend processed the event.
* Toggle to dismiss loading prompt
* Button to reset Timeline height

  + Sometimes the Timeline at the bottom is dragged very high and you are unable to reset it. This button resets the height to the default.

## Niche features

* Exporting data

  + Export of data is available with the last button of the menu on the left as seen in the image below. You can select which data you want to export and click Export selection at the bottom.
* Importing data - GeoJSON or Timeline ship data groups

On the far top right side you find the import button. When pressed, it will show a dialog where you can either import Ship data groups, by supplying the raw data of Events and/or AIS history data. You can also upload raw txt or JSON files.

There is also an option to import GeoJSON - where you can display any valid GeoJSON data. Very useful in conjunction with <https://geojson.io>, where you can copy the raw JSON on the right and paste it in. When imported, it will be displayed on the right hand side.

* Keyboard shortcuts for playback
* Timezone support  
  When clicking the selected time, it will open a Timezone menu where a custom Timezone can be selected. This will be written inside the URL with a query parameter called `timezone`. Any valid TZ identifier will work.
* Preview for socials

  + When the camera button in the bottom right menu is pressed, all unneeded menus will be removed and a 16:9 window will be displayed with the time displayed prominently at the bottom. This is useful for when you want to create a video for social media.
* CTRL+click for end of event time

  + Inside the Timeline, when you click on an event - it will move the selected time to the start time of the event. When you CTRL + click on an event - it will move the selected time to the end of the event.
* Search for infrastructure

  + When searching in the search menu, you can also search for areas and infrastructure. When clicked this will be added on your map as a layer which can be removed.
* When timeframe is too big, select start or end to bypass maxDays

  + If you request data which encompasses more than the allowed data by the backend - you can select either the first 60 days of your selected time, or the last 60 days of your selected time.
* Right mouse click on the map to copy coordinates of a location
* Copying location coordinates of ship from info panel on right
* Managed credentials / quick server swapping

  + To quickly compare the same query for multiple servers, you can click on the big Teqplay logo in the top left and login to a new server of your choice.
* Mobile support

  + The Timeline is supported on mobile, but the timeline at the bottom is not fully supported.

# Code and project structure

The project can be found in GitHub at <https://github.com/teqplay/timeline>.

#### Packages

The project is on React 16.14.0. This is currently the latest version we can use due to the project using leaflet 1.9.3, react-leaflet 1.9.0 and @teqplay/web-sdk 1.0.1.

There are several key packages this project uses:

* `leaflet` and `react-leaflet`

  + Being the core map engine, this either the most important or second most important library used inside the project. There are newer versions of this library available, but they require a rewrite of certain components.
  + leaflet-path-drag, leaflet-path-transform, react-leaflet-markercluster are all dependent on leaflet and react-leaflet library.
  + We have mostly abandoned usage of Leaflet in our projects in favor of Mapbox.
* `@teqplay/web-sdk`

  + This internal library contains several map layers used inside the map, all based for leaflet.
* `redux`, `react-redux`, `react-redux-i18n`

  + When this project originally started, React Context API did not yet exist. Therefore we chose Redux as our state management library.
  + Our translations are also done using Redux, using `react-redux-i18n`.
  + There are several different reducers, all can be found inside the `pages/**/reducers.ts` folder.
  + The reducers are initialised inside `utils/configureStore.ts`, with the root reducer inside `utils/reducers.ts`
  + Over time, our state has changed - new properties have been added and some removed. These changes can be found inside `utils/migrations.ts`
* `vis-timeline`, `react-vis-timeline`

  + This is the main Timeline component at the bottom of the page. Originally we used a different version of the React wrapper library, but this version had some bugs fixed which the originally used version had not.
* `luxon` **and** `moment`

  + For date and time management, we have 2 libraries inside this project. The reason for this is that Luxon supports Timezones out of the box and moment does not. We do however still need moment for the `vis-timeline` component.
* `sass`

  + For all styling used, we use the `sass` library. All files used related to this are `*.scss` files.
* `@sentry/react`

  + We use Sentry at Teqplay to record any errors that occur while using the application.

Regarding devDependencies, we have upgraded it to use `vite` (from originally `react-scripts`). It also includes `eslint@^9` and various type definition helper libraries.

For code linting and formatting, we use `prettier`, with a local `.prettierrc` file used for the formatting.

#### **Routes**

The main entry point for the application is `src/index.tsx`. This file introduces all HOC, such as the Redux store, Router initialisation, and primary routes. The main Routes component inside `src/routes/Routes.tsx` is used for all main logic, and routing inside the application.

The login page is outside the main Routes file.

The URL logic can be found here: <https://teqplaybv.atlassian.net/wiki/spaces/TC/pages/858882051/Timeline+old#Direct-URL-linking>.

Inside `Routes.tsx` there are a lot of actions being performed based on the URL query parameters, and based on those the `handleBrowserParamInit` function is called, which in turn will call one of the many Redux actions, which are found in the `mapDispatchToProps` function at the bottom of the file.

**Pages and Redux state approach**

Inside the main flow once you are logged in, there is really only 1 page. However, the `pages` folder contains all the logic for the main individual parts of the application. These parts introduce the Redux state in the application and handle the overhead of using the Redux Actions. Some of these are still Class based components.

It is split up as follows:

* Login

  + Login page
  + Contains Authorization actions, reducers
* Map

  + Contains the inner Map content
  + Contains the Custom layers of the Map, which imports from various sources
  + Includes **many** Redux actions of settings related to the map or the Timeline tool
* MenuBar

  + Only component without a separate Redux reducer
  + Includes all Dialog components; CredentialsManager, CompareDialog, ImportDialog, Search…
  + Uses some Redux actions from `ship`
* Ship

  + No real rendered output
  + Whenever the application changes URL query parameters, this component will actually trigger the proper functions to execute fetching
  + Includes the `<title>` of the page
  + Includes actions for API fetching, loading and data storage

The main Redux configuration can be found in `src/utils/configureStore.ts` and `src/utils/reducers.ts`.

A note is that over time, the Redux state of the application has changed slightly. The `src/utils/migrations.ts` file handles all the changes that have been made over time. Every change causes the `version` inside the `persistConfig` to be incremented by 1.

#### Notable components

This tool introduces many custom components, of which some are important to highlight.

* `credentialsManager/CredentialsManager.tsx`

  + Main entry point to change between logged in servers.
* `loadingComponent/LoadingComponent.tsx`

  + Handles all loading steps, custom loading entries and substeps. Set-up in quite a complex way with retry on error, non-critical errors.
  + See `src/pages/ship/loadingActions.ts` for all related actions to the `LoadingComponent`.
* `map/**/**.tsx`

  + Includes all map related custom components, such as Layers, icons or traces.
* `shipMenu/ShipMenu.tsx`

  + Renders the side ShipMenu, including all sub tabs which are found in this folder.
* `timeline/Timeline.tsx`

  + Renders the main Timeline component at the bottom of the screen.

#### State

As mentioned, we mostly use Redux for handling state in the application. There is 1 HOC with a React Context approach, the `TimezoneProvider`. This handles in which Timezone the application should show all timestamps.

All other states are handled in-component with the useState hook and trinkling down state to lower components.

The data from API calls used in many components is stored inside the `ship` reducer.

#### API

All calls to external API are done inside the `TeqplayAPIService` class. There is one private`fetchAPICall<T>` function, which is used by the other functions in this class to compose API call functions and export these to the application.

The APIService is introduced inside the `Routes.tsx` file, and trinkled down to all components which need it. We chose this at the time because React Context did not yet exist.

#### Utility functions

All relevant utility functions are in the `utils` folder. There are several notable files in the `src/util` folder:

* `events.ts`

  + Contains many functions related to events which are **key** for the Timeline to function properly. Many of these events are either looking up related events to 1 event (i.e. matching end with start event), or functions to extract generics like a name or type from an event.
* `mapUtils.ts`

  + These functions are key for the map components to display properly. Several functions are related to handling AIS data, such as interpolation between 2 timestamps. Includes many generic functions related to AIS data, like getting the ship length, height, width etc.
