# AWS sdk 1.x -> 2.x

**Space:** TC  
**URL:** https://teqplaybv.atlassian.net/wiki/spaces/TC/pages/824803329  

## Content

This document is to provide some tips and pointers for migrating a project from the AWS Java SDK version 1 to version 2. This guide is based on Timeline, it will differ per project. The [AWS Kotlin SDK](https://aws.amazon.com/sdk-for-kotlin/) was tried as well, but dropped due to issues with OkHttp, and the latest version needs Kotlin 2.1+, where most of Teqplay’s projects are still on 1.9.

The Copilot agent was a great help with migrating the AWS SDK to version 2. Using Claud sonnet 4, there were only some small tweaks to make, listed below, as well as the full examples of the changes.

## Copilot’s errors

There were only two points to check in Timeline after letting copilot perform the changes, but the experience will vary, so check the code!

### Unsafe .available()

The putObject function now needs a RequestBody instead of an InputStream, and the RequestBody needs the content length. This length can be gotten from the InputStream with .available(), but the reliability depends on the implementation of it, so overall it’s unsafe to use. In Timeline the stream is now first put in a byte array, but this method uses extra ram, so check what’s best for your application.

### Close the stream

The getObject in the S3Client now returns an InputStream. It is safe practice to close any stream after use, to prevent leaks. Copilot did not do this at first, so make sure it’s closed by calling InputStream.close(), or by performing the actions in a .use {} block.

## Gradle changes

This:

kotlinwide760implementation("com.amazonaws:aws-java-sdk-s3:$amazon\_aws\_version")

Should now be:

kotlinwide760implementation("software.amazon.awssdk:s3:$amazon\_aws\_version")

The latest version can be found [here](https://mvnrepository.com/artifact/software.amazon.awssdk/s3).

## S3Configuration example

The s3Client bean from Timeline is shown here. The AmazonS3ClientBuilder has been swapped out for the S3Client.builder(), which when built returns an S3Client object instead of an AmazonS3 one. The credentials object creation is now more streamlined with AwsBasicCredentials.create(…)

AWS 1.x:

kotlinwide760@Bean
fun s3Client(): AmazonS3 {
return AmazonS3ClientBuilder.standard()
.withRegion(aws.region)
.withCredentials(
AWSStaticCredentialsProvider(
object : AWSCredentials {
override fun getAWSAccessKeyId() = aws.key
override fun getAWSSecretKey() = aws.secretKey
})
)
.build()
}

AWS 2.x:

kotlinwide760@Bean
fun s3Client(): S3Client {
val credentials = AwsBasicCredentials.create(aws.key, aws.secretKey)
return S3Client.builder()
.region(Region.of(aws.region))
.credentialsProvider(StaticCredentialsProvider.create(credentials))
.build()
}

## S3Service example

The S3Service in timeline has changes to both the upload and download functions.

### Upload

The ObjectMetadata is replaced by the PutObjectRequest.builder(), with now the path and fileName also being set on the builder. A notable change is the loading of the stream into a byte array. This is done here as RequestBody.fromInputStream(…) requires the content length, which can be gotten from an InputStream using .available(), but this is unreliable. Using the byte array makes it reliable, but the downside is that the entire stream is loaded into memory. It’s fine if the objects aren’t that big, but if they are, you should look into using the InputStream directly. The s3Client is now also directly imported instead of the s3Configuration, this is not necessary, but it makes for cleaner code (line 14 versus line 22).

AWS 1.x:

kotlinwide1011fun upload(
path: String,
fileName: String,
optionalMetaData: Optional<Map<String?, String?>>,
inputStream: InputStream?
): PutObjectResult? {
val objectMetadata = ObjectMetadata()
objectMetadata.contentType = "application/zip"
optionalMetaData.ifPresent { map ->
if (map.isNotEmpty()) {
map.forEach(objectMetadata::addUserMetadata)
}
}
return s3Configuration.s3Client().putObject(path, fileName, inputStream, objectMetadata)
}

AWS 2.x:

kotlinwide1011fun upload(
path: String,
fileName: String,
optionalMetaData: Optional<Map<String?, String?>>,
inputStream: InputStream?
): PutObjectResponse? {
val putObjectRequestBuilder = PutObjectRequest.builder()
.bucket(path)
.key(fileName)
.contentType("application/zip")
optionalMetaData.ifPresent { map ->
if (map.isNotEmpty()) {
putObjectRequestBuilder.metadata(metadata)
}
}
return inputStream?.let { stream ->
// Read the entire stream into a byte array, as with an InputStream it would need the content length,
// which cannot be reliably determined beforehand.
val bytes = stream.readBytes()
s3Client.putObject(
putObjectRequestBuilder.build(),
RequestBody.fromBytes(bytes)
)
}
}

### Download

The download function has minimally changed; a builder is now used and the request is wrapped in a try/catch. Also the direct use of the s3Client, instead of s3Configuration.s3Client()

AWS 1.x:

kotlinwide760fun download(path: String, fileName: String): S3Object? {
return s3Configuration.s3Client().getObject(path, fileName)
}

AWS 2.x:

kotlinwide760fun download(path: String, fileName: String): InputStream? {
val getObjectRequest = GetObjectRequest.builder()
.bucket(path)
.key(fileName)
.build()
return try {
s3Client.getObject(getObjectRequest)
} catch (\_: Exception) {
null
}
}

## SnapshotController example

An example from the SnapshotController in Timeline where the S3Service.download function is used. This now returns an InputStream instead of an S3Object, so it must be closed to prevent leaks. A .use {} block takes care of this, but you can also use .close().

AWS 1.x:

kotlinwide760private fun HttpServletResponse.setFileContent(snapshotId: String) {
val snapshot = s3Service.download(awsProperties.bucket, snapshotId)
?: throw NotFoundException("Snapshot not found")
this.contentType = snapshot.objectMetadata.contentType
this.addHeader("Content-Disposition", "attachment; filename=$snapshotId")
this.outputStream.write(snapshot.objectContent.readBytes())
this.outputStream.flush()
this.outputStream.close()
}

AWS 2.x:

kotlinwide760private fun HttpServletResponse.setFileContent(snapshotId: String) {
val snapshotStream = s3Service.download(awsProperties.bucket, snapshotId)
?: throw NotFoundException("Snapshot not found")
// .use to close the stream automatically after use
snapshotStream.use { stream ->
this.contentType = "application/zip"
this.addHeader("Content-Disposition", "attachment; filename=$snapshotId")
this.outputStream.write(stream.readBytes())
this.outputStream.flush()
this.outputStream.close()
}
}
