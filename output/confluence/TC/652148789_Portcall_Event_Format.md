# JSON formats

## Event

{
uuid : string
eventType : string // From event type enumeration
source : string
port : string
recordTime: string // ISO 8601 datetime with timezone, time of sending event
eventTime: string // ISO 8601 datetime with timezone, estimation or actual time of the event content
ship : {
// At least one of the following identifiers must be provided, preferably IMO
imo ?: string
eni ?: string
mmsi ?: string
}
portcallId ?: string // Port call identifier, this must be an UCRN for NLRTM and NLAMS
location ?: {
type : string // From location enumeration
name ?: string
}
context ?: {} // See Event context specification
}

## Event Context

The event context can contain any combination of the following keys, if they make sense for that event

##### `agent`

`agent: string` Agent code as defined in HaMIS in ALL CAPS without spaces

##### `distanceToLocationNM`

`distanceToLocationNM: number`

Distance the `ship` is to the `location` at `recordTime` in nautical miles

##### `mooring`

Information on how the `ship` is moored to the `berth` `location`

mooring : {
bollardFore : number // Bollard the fore of the ship is moored at, integer or integer + 0.5
bollardAft : number // Bollard the aft of the ship is moored at, integer or integer + 0.5
doubleBanked ?: boolean // If the ship is moored side-by-side to another ship (which is closer to the berth). Defaults to false
}

##### `movementId`

`movementId : string`

identifier which links the `ship` movement from one `location` to another (e.g. a `pilotBoardingPlace` to a `berth`). In NLRTM for movements from and to `pilotBoardingPlace`s and `berth`s this should be the movement identifier generated by HaMIS

##### `serviceShipMMSI`

`serviceShipMMSI : string`

If a vessel is providing a service (e.g. `bunkerService`) to the `ship`, this can be that vessels MMSI.

#### `vesselName`

`vesselName : string`

Vessel name at the time of the event

#### `berthVisitId`

`berthVisitId : string`

Identifier from a source uniquely identifying a berth call/visit. Can be added to `berth.[e/a]t[a/d]` events and services coupled to a berth call such as `cargoOperations`.

A berthVisitId MUST be prefixed with `PRONTO-BC` and SHOULD include a dash, the source, a dash and a freeform identifier afterwards. Examples:

PRONTO-BC-King-38cd8f28-8f17-4b13-a68a-63ca3538a9e7
PRONTO-BC-APMT-LZELDMO0817
PRONTO-BC-TEQPLAY-38cd8f28-8f17-4b13-a68a-63ca3538a9e7
